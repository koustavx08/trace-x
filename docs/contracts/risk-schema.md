# Risk Scoring Schema

> **Status:** Baseline reference (pre-parallel-merge). Derived from `apps/api/src/analytics/risk_engine.py` and
> `apps/api/src/api/v1/risk.py`.

## `RiskFactorType` (12 factor types)

```
MIXER_INTERACTION, PEEL_CHAIN, ROUND_AMOUNTS, RAPID_MOVEMENT, HIGH_RISK_ENTITY,
SANCTIONS_HIT, LARGE_VALUE_TRANSFER, CROSS_CHAIN_BRIDGE, NEW_WALLET,
LOW_LIQUIDITY_TOKEN, CONTRACT_INTERACTION, DUSTING_ATTACK
```

Note: `LOW_LIQUIDITY_TOKEN` and `DUSTING_ATTACK` are defined in the enum and have entries in `RISK_WEIGHTS`, but no
corresponding `_check_*` method exists in `RiskScoringEngine` as of baseline — only 10 of the 12 factor types are
actually evaluated by `assess_wallet` (`MIXER_INTERACTION` through `CONTRACT_INTERACTION`, skipping those two). Treat
"12 risk factors" (as claimed in `_get_methodology()`'s docstring-like text) as aspirational until the two missing
checks are implemented.

## `RiskSeverity`

`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFO` — thresholds on the 0–100 overall score:

| Severity | Threshold |
|---|---|
| CRITICAL | ≥ 80 |
| HIGH | ≥ 60 |
| MEDIUM | ≥ 40 |
| LOW | ≥ 20 |
| INFO | < 20 |

## `RiskFactor`

```python
factor_type: RiskFactorType
severity: RiskSeverity
score: float                 # 0–100, factor-specific
weight: float                 # from RISK_WEIGHTS
description: str
evidence: dict                # factor-specific structured evidence (tx hashes, hop counts, etc.)
confidence: ConfidenceLevel
weighted_score: float          # computed property = score * weight
```

## `RiskAssessment`

```python
overall_score: float          # weighted-average of triggered factors, capped
risk_level: RiskSeverity
factors: list[RiskFactor]
summary: str                   # human-readable rollup, generated by _generate_summary
methodology: str                # fixed methodology description string
assessed_at: datetime
```

## Overall-score formula (`_calculate_overall_score`)

```
base_score   = sum(factor.weighted_score for factor in factors) / sum(factor.weight for factor in factors)
max_possible = max(factor.score for factor in factors)
overall_score = min(base_score * 1.1, max_possible, 100.0)
```
A 10% boost is applied to the weighted average, then capped at both the single highest triggered factor's raw score
and 100. Wallets with zero triggered factors score `0.0`.

## Per-factor trigger conditions (summarized from `_check_*` methods)

| Factor | Trigger | Severity/score logic |
|---|---|---|
| MIXER_INTERACTION | `graph_context["mixer_interactions"]` non-empty (from `graph_queries.find_mixer_interactions`) | Always CRITICAL / 95 |
| PEEL_CHAIN | `graph_context["peel_chains"]` entries whose `origin == wallet.address.lower()` | Always HIGH / 85 |
| ROUND_AMOUNTS | ≥3 transactions with whole-ETH values ≥1 | HIGH-count (≥5) → MEDIUM/60, else LOW/35 |
| RAPID_MOVEMENT | ≥3 tx pairs <300s apart (sorted by timestamp) | ≥5 sequences → HIGH/75, else MEDIUM/50 |
| HIGH_RISK_ENTITY | `entity_data["entity_type"]` in `{MIXER, SANCTIONED, DARKNET, GAMBLING}` | Per-type fixed severity/score (SANCTIONED=100, MIXER=95, DARKNET=90, GAMBLING=70) |
| SANCTIONS_HIT | `entity_data["entity_type"] == SANCTIONED` | Always CRITICAL / 100, confidence forced to CONFIRMED |
| LARGE_VALUE_TRANSFER | any tx ≥100 ETH | max ≥1000 ETH → HIGH/70, else MEDIUM/50 |
| CROSS_CHAIN_BRIDGE | tx with a bridge-token symbol (USDC/USDT/WETH/MATIC) AND method containing `"bridge"` | Always MEDIUM / 45 |
| NEW_WALLET | `tx_count < 5` and wallet age <30 days (from `first_seen`) | Always LOW / 25 |
| CONTRACT_INTERACTION | >10 non-`"transfer"`-method transactions | Always LOW / 30 |

## API surface

`POST /risk/wallets/{wallet_id}/assess` → `RiskAssessmentResponse` (flattened `RiskAssessment.to_dict()`). Note the
current implementation builds "fake" `GraphTransaction`-shaped objects on the fly using `type(...)` (a dynamic class)
rather than importing the real `GraphTransaction` dataclass — functionally equivalent for attribute access but worth
knowing when refactoring `src/api/v1/risk.py::assess_wallet_risk`.

`GET /risk/cases/{case_id}/risk-summary` computes its own simplified risk buckets directly off `Wallet.risk_score`
(≥75 critical / 40–75 medium / 20–40 low / <20 info) — note this bucketing is **not** the same as `SEVERITY_THRESHOLDS`
above (e.g. no "high" bucket is populated; `"high": 0` is hardcoded) — a discrepancy worth reconciling, not a WS8
change since it's owned by other workstreams' files.
